# Brief dependency review

9 October 2026. Scope: current stable versions, maintenance signals, and obvious successor candidates. This is a restart check, not an exhaustive security or ecosystem audit.

## Result

Keep the Leptos/Tauri approach and the mainstream Rust libraries. Update their stable releases. The most useful replacement investigation is the HTML extraction stack; the most consequential maintenance decision is Cozo. This pass found no evidence of a universally endorsed, compatible successor that justifies changing frameworks or storage as part of routine dependency upkeep.

| Area | Finding | Decision |
| --- | --- | --- |
| UI and desktop | Leptos 0.8.22 / router 0.8.17 and Tauri 2.12.2 are current stable releases. Leptos 0.9 is in prerelease. | Updated the stable lines. Keep the existing CSR/Trunk/Tauri architecture. Added a separate WASM/CSR lint check because the default native frontend build uses SSR. See [Leptos release](https://github.com/leptos-rs/leptos/releases/tag/v0.8.22) and [Tauri update guidance](https://v2.tauri.app/develop/updating-dependencies/). |
| Networking, parsing, sanitization | Reqwest, feed-rs, Ammonia, Tokio, Serde, and the existing supporting crates have current stable releases. No compelling migration trigger emerged in this short review. | Updated versions and retained the libraries. Adapted feed-rs 3's optional author names, with regression tests for missing and blank names and feed-level fallback. |
| Identity and encrypted keys | Dalek 3, Argon2 0.6, and ChaCha20Poly1305 0.11 are stable major updates within the existing implementations. | Updated, using `getrandom::fill` directly for operating-system randomness. Froze format-v1 Argon2 parameters and added fixtures generated by the previous crypto versions to verify decryption and exact canonical signatures. See [Dalek changelog](https://github.com/dalek-cryptography/ed25519-dalek/blob/main/CHANGELOG.md) and [Argon2 changelog](https://github.com/RustCrypto/password-hashes/blob/master/argon2/CHANGELOG.md). |
| HTML tree and article extraction | Kuchiki is archived and has an [unmaintained RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2023-0019.html). `readable-readability` 0.4 also depends on Kuchiki; its repository's last push was April 2024. | Plan a small comparison of [dom_query](https://github.com/niklak/dom_query) and [dom_smoothie](https://github.com/niklak/dom_smoothie) against our extraction/sanitization fixtures. These are actively maintained candidates, not established drop-in replacements. Replacing only the direct Kuchiki usage would leave the transitive dependency. Check text offsets, highlights, lazy images, math, tables, malformed HTML, and sanitization before choosing. |
| Storage | Cozo 0.7.6 remains the latest published release, [released in December 2023](https://github.com/cozodb/cozo/releases/tag/v0.7.6). The repository is not archived; the GitHub API reports its last push in December 2024. | Retained. Its Validity/Datalog model is part of Carrel's architecture, so replacement needs a separate design decision covering migrations, latest-fact semantics, queries, and the future sync bridge. Release age alone does not establish a functional defect. |
| Math and robots | `katex` 0.4.6 and `texting_robots` 0.2.2 remain the latest releases. Their repositories show little recent activity. KaTeX's Rust wrapper brings an embedded QuickJS dependency. | Retained. Review the bundled math engine/runtime when touching extraction; preserve offline MathML rendering. Keep robots behavior covered by fixture tests. No clearly preferred compatible successor was established in this brief pass. See [KaTeX wrapper](https://github.com/xu-cheng/katex-rs) and [robots parser](https://github.com/Smerity/texting_robots). |

Repository activity is a maintenance signal, not a quality score. Candidate extraction libraries were inspected, not benchmarked or adopted. Kuchiki's cited advisory is an informational maintenance advisory.

The self-sync implementation on 10 October adds a compatible current family:
[Iroh 1.3.0](https://crates.io/crates/iroh/1.3.0),
[iroh-docs 0.101.0](https://crates.io/crates/iroh-docs/0.101.0),
[iroh-blobs 0.103.1](https://crates.io/crates/iroh-blobs/0.103.1), and
[iroh-gossip 0.101.0](https://crates.io/crates/iroh-gossip/0.101.0).
Their Rust minimum is 1.91. These dependencies now run the persistent private
protocol host, with current endpoint hooks covering both incoming and outgoing
authorization. Direct defaults are disabled; docs/blobs use filesystem storage,
gossip uses its network feature, and Iroh uses ring TLS and native networking.
No remote RPC service is enabled. `futures-core` is an already-transitive,
test-only dependency for observing the real denied document-sync result.

## Applied version changes

The 18 October backup implementation adds `age` 0.12.1 with default features
disabled, using only passphrase streaming encryption. Its explicit scrypt work
limit bounds untrusted backup headers. Cozo's existing `storage-sqlite` feature
provides the full snapshot container; active storage stays RocksDB. These choices,
format bounds and recovery ownership are recorded in
[ADR 0005](ADR-0005-local-backup-recovery.md). Locked dependency notices regenerate
successfully through the existing cargo-about policy, including the additional
crypto and SQLite dependencies. This is a scoped backup dependency decision,
separate from the historical general review above.

The manifests and lockfile were refreshed to current stable releases compatible with the workspace's Rust 1.95 requirement. Rust 1.99 stable is already installed on this machine; the workspace minimum stays at 1.95.

## Verification

- `just check` passed on macOS with Rust 1.99: formatting, native Clippy with warnings denied, all 130 tests, and WASM/CSR Clippy with warnings denied.
- Legacy encrypted-master-key and exact fact-signature fixtures passed with the new crypto libraries.
- Trunk CSR build passed, including wasm-bindgen 0.2.129 generation and the frontend's fonts/styles/assets. Trunk required `NO_COLOR=true` in this tool environment, whose inherited `NO_COLOR=1` value was rejected by its CLI parser.
- Linux CI and interactive desktop testing were not run locally.

Builds used `CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0` to limit disk use while space was being cleared. Those are session overrides, not changes to the project's build profiles.
